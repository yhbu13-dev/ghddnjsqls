# BevFlow 운영 관제

카페 · 사우나 · 식당에 **카페 품목 · 스낵 품목 · 음료 품목**을 납품하는 운영팀용 실사용 도구입니다.

- 점주는 **카카오톡 채널에서 버튼만 눌러** 발주합니다 (채팅 속 품목 카드, 또는 한눈에 보는 모바일 발주 화면).
- 매장 업종에 맞는 품목만 보이고, 다른 품목은 **신청 → 운영자 승인** 후 열립니다.
- 식당 음료는 POS 판매 로그로 재고를 추정해 발주를 먼저 제안하고, 사장님 승인 → 결제 → 당일 배송 → 티오더 정산까지 처리합니다.

- **운영 콘솔** (`/`, 로그인): 관제 홈 · 재고 관제 · 발주 관제 · 알림톡 모니터 · 배송 관제 · 파일럿 리포트 · 관리 (품목 승인·카카오 포함)
- **카카오톡 채널 챗봇** (`POST /api/kakao/skill`): 카카오 i 오픈빌더 스킬 서버. 품목 카드의 [+1박스] 버튼 → 장바구니 → [발주 확정], 지난번과 똑같이, 발주 현황, 품목 추가 신청.
- **점주 발주 화면** (`/m/…`): 채널의 [한눈에 발주하기] 버튼·카카오 로그인으로 여는 모바일 화면. 품목 탭 · 소분류 칩 · − / + · 하단 합계 바 · 발주 내역. 장바구니는 챗봇과 공유합니다.
  사우나처럼 품목이 40종 넘는 매장은 **발주서 방식**: 정기 발주 요일 아침에 지난번 수량으로 채워진 발주서가 오고, 매대 순서로 바뀐 줄만 고쳐 확정합니다.
- **관리자 카톡 알림**: 운영자 본인 카카오톡(나와의 채팅)으로 발주 확정 · 품목 신청 · 정기 발주서 발송 · 미확정 발주서(11:30) · 출고 합계(11:50) · 배송 결과. 버튼은 **모바일 발주 내역** (`/a`: 오늘 요약 · 출고 집계 · 발주 내역)으로 열립니다.
- **사장님 승인 페이지** (`/o/…`): 알림톡 버튼으로 여는 링크. 로그인 없이 발주를 승인하거나, 수량을 고치거나, 보류합니다.
- **기사 배송 페이지** (`/d/…`): 배차 때 발급되는 링크. 도착 → 하차 전 잔량 입력 → 하차 완료 순서로 진행합니다. 입력한 잔량은 재고 추정 보정에 바로 쓰입니다.
- **스케줄러**: 1분마다 발주 트리거 점검 · 예약 발송 · 리마인드 · 무응답 만료 · 13:30 배차 · 시간별 재고 기록을 돌립니다.

Node.js 22 내장 모듈만 쓰고 외부 패키지가 없습니다(`npm install` 불필요). 데이터는 SQLite 파일 하나에 저장하며, 50~500개 매장 파일럿은 작은 VM 한 대로 충분합니다.

## 빠른 시작 — 파일 하나로 실행

**`dist/bevflow.js`** 한 파일에 서버 · 화면 · 스크립트가 모두 들어 있습니다. 이 파일만 복사하면 됩니다(Node.js 22.13 이상).

```bash
node bevflow.js seed-sample      # (선택) 식당 50 · 카페 3 · 사우나 3곳 · 6주 샘플 데이터 — 실제 엔진으로 시뮬레이션
node bevflow.js                  # 서버 실행 → http://localhost:8080
node bevflow.js backup           # DB 온라인 백업 (backups/, 30일 보관)
node bevflow.js create-admin ops@회사.kr 홍길동   # 관리자 추가·비밀번호 분실 시 재설정
node bevflow.js help
```

데이터는 파일 옆 `data/bevflow.db`에 저장됩니다(`BEVFLOW_DB`로 변경). 첫 실행 때 관리자 계정이 만들어지고, 터미널에 임시 비밀번호가 출력됩니다. 첫 로그인에서 비밀번호를 바꿔야 합니다. 이메일과 비밀번호를 미리 정하려면 `BEVFLOW_ADMIN_EMAIL`, `BEVFLOW_ADMIN_PASSWORD`를 설정하세요.

### 소스에서 개발할 때

```bash
npm start                  # 소스 그대로 실행 (npm run seed:sample · backup · create-admin 도 같음)
npm test                   # 엔진·API·통합·점주 발주·카카오·정기 발주서·관리자 알림·단일 파일 테스트 30개
npm run bundle             # 소스를 고친 뒤 dist/bevflow.js 다시 만들기 (안 하면 테스트가 알려 줌)
```

## 실제 운영 시작 순서

1. **서버 배포**: HTTPS 주소를 마련합니다(`deploy/` 참고). [관리 → 운영 설정 → 외부 접속 주소]에 그 주소를 넣어야 사장님·기사 링크가 올바르게 만들어집니다.
2. **샘플 삭제**: 샘플 데이터를 넣었다면 [관리 → 데이터 연동 → 샘플 데이터 전체 삭제]로 지웁니다.
3. **마스터 등록**: [관리]에서 SKU(박스 단가) → 권역(거점 좌표) → 기사 → 매장 순서로 등록합니다. 매장은 CSV로 한 번에 가져올 수 있습니다.
4. **메뉴 매핑**: 티오더 POS 메뉴명을 SKU에 연결합니다. 세트 메뉴는 SKU별로 여러 줄로 매핑합니다. 매핑되지 않은 메뉴는 [SKU·메뉴 매핑 → 미매핑 POS 메뉴]에 쌓입니다.
5. **초기 잔량 입력**: 매장마다 현재 음료 잔량을 한 번 입력합니다. 이 시점부터 재고 추정과 발주 제안이 시작됩니다.
6. **POS 로그 연결**: 티오더가 `POST /api/ingest/pos`로 판매 로그를 보내도록 협의합니다(서명 방식은 `docs/INTEGRATIONS.md`). 연동 전에는 CSV로 판매 기록을 올려도 됩니다.
7. **카카오 채널·챗봇·관리자 알림**: `docs/KAKAO.md` 순서대로 채널 → 오픈빌더 스킬 → 블록 ID → (선택) 카카오 로그인을 설정하고, 매장마다 [관리 → 품목 승인·카카오 → 연결 코드]를 발급해 점주께 전달합니다. 식당이 아닌 카페·사우나는 POS 연결·초기 잔량 없이 이것만으로 발주를 받을 수 있습니다.
8. **알림 발송**: 처음에는 **콘솔 모드**로 시작합니다. 메시지가 [알림톡 모니터]에 쌓이면 [메시지·링크 복사]로 사장님 카카오톡에 전달합니다. 알림톡 대행사 계약과 템플릿 승인이 끝나면 **웹훅 모드**로 바꿉니다.
9. **결제**: 기본값은 **후불 청구**(월말)입니다. PG 계약 후 카드 자동결제 어댑터를 추가합니다.

매일 할 일과 경보별 대응은 `docs/OPERATIONS.md`에 있습니다.

## 무엇이 실제로 돌아가고, 무엇이 연결을 기다리나

| 영역 | 상태 |
|---|---|
| 업종별 품목(카페·스낵·음료) · 품목 이용 신청/승인 · 점주 직접 발주(최소 금액·중복 접수 방지) · 공유 장바구니 · 지난번과 똑같이 | 동작 |
| 카카오톡 채널 챗봇(오픈빌더 스킬 v2 응답) · 연결 코드 매장 연결 · 모바일 발주 화면 | 동작, **채널 개설·오픈빌더 봇 배포 필요** |
| 카카오 로그인(휴대폰 번호 자동 연결 · 채널 appUserId 인식) | 동작, **카카오 디벨로퍼스 앱 등록 필요 (선택)** |
| 정기 발주서(사우나) · 관리자 카톡 알림(나에게 보내기) · 모바일 발주 내역 `/a` | 동작, **관리자 알림은 카카오 디벨로퍼스 앱 + 운영자별 연결 필요** |
| 재고 추정 (POS 판매 → 박스 환산 × 누수 보정 α, 오차 밴드, 실사 리셋·α 학습) | 동작 |
| 발주 트리거 · 묶음 제안 · 야간/브레이크타임 예약 발송 · 검수 대상 매장 | 동작 |
| 사장님 승인·수량 수정·보류 (서명 링크), 운영자 대리 승인(사유 기록), 리마인드, 3시간 무응답 만료, 다음 날 재제안 | 동작 |
| 컷오프(12:00) · 배송 요일 · 13:30 자동 배차 · 최근접 순서 · ETA · 기사 링크 · 배송 실패 시 재배차 | 동작 |
| 주차별 티오더 정산 (수수료 3%) · CSV 내역서 · 지급 완료 처리 | 동작 |
| 계정·권한(관리자/운영자/열람) · 로그인 시도 제한 · CSRF 방어 · 감사 이벤트 로그 | 동작 |
| 티오더 POS 로그 수신 | 수신 API·서명 검증 완료, **티오더 측 발송 협의 필요** |
| 카카오 알림톡 발송 | 콘솔 기록(수동 전달)·웹훅 발송 동작, **대행사 계약·템플릿 승인 필요** |
| 카드 자동결제 | 후불 청구·샌드박스 동작, **PG 계약 후 어댑터 추가 필요** (`server/adapters/payment.js`) |

## 구조

```
server/
  index.js            서버 진입점 (첫 실행 시 관리자 생성, 스케줄러 시작)
  app.js · http.js    HTTP · 보안 헤더(CSP, no-referrer) · 세션 · CSRF
  routes.js           API (콘솔 · 관리 · POS 수신 · 사장님/기사 링크 · 점주 발주 화면 · 카카오)
  kakao.js            카카오 오픈빌더 스킬(챗봇) · 카카오 로그인 · 매장 연결
  db.js               SQLite 스키마·마이그레이션
  settings.js         운영 설정 (검증 규칙 포함)
  jobs.js             1분 스케줄러
  engine/             inventory · proposals · orders · delivery · settlement · messages · catalog(품목·권한) · shop(점주 발주)
  adapters/           notifier(console/webhook) · payment(invoice/sandbox_card)
public/               console · login · owner · driver · shop(점주 발주) · kakao-link 페이지 (빌드 없음)
scripts/              seed-sample · backup · create-admin · bundle(단일 파일 빌드)
dist/bevflow.js       단일 실행 파일 (위 전부를 묶은 결과물 — 직접 고치지 말 것)
test/                 node:test 테스트
deploy/               systemd · Caddy(HTTPS) · Dockerfile
demo/index.html       투자자 미팅용 오프라인 데모 (서버 없이 열리는 단일 HTML)
```

## 참고

- 모든 시각은 한국 표준시(KST) 기준입니다.
- 샘플 데이터의 매장명·연락처·차량번호는 모두 가상입니다(연락처는 `010-0000-xxxx`).
- 투자자·파트너 시연에는 `demo/index.html`(오프라인 데모)을 그대로 쓸 수 있습니다. 실제 운영 데이터는 이 도구에서 나옵니다.
