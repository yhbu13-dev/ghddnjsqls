# BevFlow 운영 관제 콘솔 — 시연용 데모

식당 POS 판매 로그로 음료 재고를 추정하고, 카카오 알림톡으로 승인받아 당일 배송하는 B2B 음료 유통 플랫폼 **BevFlow**의 본사 운영팀용 관제 대시보드 데모입니다.

- **파일 하나(`index.html`)로 끝납니다.** 외부 CSS·JS·폰트·이미지·CDN을 쓰지 않으므로 인터넷이 없는 회의실에서도 더블클릭으로 열립니다.
- 데이터는 파일 안의 시뮬레이션 엔진이 만듭니다. 파일럿 6주(50개 매장 · 3개 권역 · 기사 3명)를 15분 단위로 돌려 POS 판매 → 재고 추정 → 발주 제안 → 알림톡 승인 → 결제 → 출고 → 배송 → 정산까지 생성합니다.
- 시드가 고정돼 있어 **[데모 데이터 리셋]을 누르면 언제든 같은 장면으로 돌아갑니다.** 날짜는 실행한 날을 "오늘"로 잡고, 시각은 **오늘 14:20**에서 실제 시간과 같은 속도로 흐릅니다(배송이 진행 중인 오후).
- 기준 화면은 1440×900 노트북이며, 좁은 화면에서는 한 열로 쌓입니다.

## 3분 시연 순서

| 순서 | 화면 (단축키) | 누를 것 / 보여줄 것 | 말할 것 |
|---|---|---|---|
| 1 | 관제 홈 `1` | 상단 KPI 6개 훑기 → 우측 "파일럿 검증 지표" | "50개 매장이 지금 이렇게 돌고 있습니다" |
| 2 | 재고 관제 `2` | 기본 선택 매장 `역삼 달빛포차 · 콜라 1.25L`. 음영 밴드, 안전재고 점선, 오늘 00:56 트리거 링, 기사 실사 편차 막대, 14:41 입고 예정 | "밴드가 오차 범위이고, 하한이 안전재고에 닿는 순간 발주를 제안합니다" |
| 3 | 알림톡 모니터 `4` | 같은 매장 대화: 새벽 트리거 → 09:00 발송(야간 생성분) → 09:07 승인 → "금일 15시 도착 예정" | "사장님께는 이 한 통이 갑니다" |
| 4 | 발주 관제 `3` | **승인 대기** 카드의 **[승인 시뮬레이트]** 클릭 → 카드가 결제 완료로 이동, KPI 증가, 토스트 | 직접 눌러 보여주기 |
| 5 | 배송 관제 `5` | 라우트 뷰, 기사 카드, 정차 시간 히스토그램(목표선 7분), 배송 용량 산식 | "정차당 평균 6.8분, 설계 용량 기사 1인 60곳" |
| 6 | 파일럿 리포트 `6` | 3대 지표 카드, 주차별 추이, 티오더 정산 요약 → [정산 내역서] | "이 세 지표로 평가받겠습니다. 티오더 정산도 여기서 나갑니다" |

그 밖에 동작하는 것:

- 관제 홈 "지금 조치 필요": [재결제 요청], [리마인드], [선제 제안]
- 발주 관제: [즉시 발송]
- 알림톡 폰 화면: [승인], [수량 수정], [보류]
- 상단 권역 필터(전체·강남권·마포권·성수권): 모든 화면에 적용
- 상태 배지를 누르면 그 상태만 걸러 봅니다.
- 시계가 실제 시간으로 흐르기 때문에 화면을 열어 두면 배송이 진행됩니다. 약 2분 반 뒤 강남권 기사가 하차를 시작하고, 8분 뒤 첫 배송 완료 알림이 뜹니다.

## 사업 가정과 화면 수치의 일치

| 가정 (피치덱) | 화면 수치 | 위치 |
|---|---|---|
| 매장당 월 GMV 80만 원 | 79.4만 원 (W2–W6 환산) | 리포트 상단 |
| 평균 상품 단가 21,500원 | 박스 단가 21,492원 | 리포트 상단 |
| 매장당 주 1회 배송, 회당 8~9개 하차 | 매장당 주 약 1.0회, 회당 8.1박스 | 배송 용량 카드 · 리포트 상단 |
| 승인율 목표 85% 이상 | 최근 2주 87.8% (누적 83.0%, W1 76.1% → W6 88.7%) | 리포트 |
| 정차 시간 목표 7분 이내 | 최근 2주 평균 6.8분 (P90 8.6분) | 배송·리포트 |
| 재고 추정 오차 (목표 10% 이내로 설정) | 최근 2주 9.2% (W1 11.6% → W6 9.3%), 밴드 적중률 92% | 리포트 |
| 배송원 1인 1일 60곳 | 설계 용량으로 표시, 현재 가동률 3.9% | 배송 용량 카드 |

> 파일럿은 50개 매장이 주 1회 배송이라 하루 정차가 3명 합쳐 7곳 안팎입니다. 그래서 기사 카드는 "38/60" 같은 가상의 물량 대신 실제 파일럿 물량(예: 2/4)을 보여 주고, 60곳은 **설계 용량**으로 따로 표시합니다. 산식은 3명 × 60곳 × 주 6일 ≈ 1,080개 매장입니다.
>
> 추정 오차 목표(10%)는 브리프에 수치가 없어 임의로 정한 값입니다. 덱의 목표치가 따로 있으면 `TARGET.error`만 바꾸면 됩니다.
